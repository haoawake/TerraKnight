# 守望者骑士：晶塔返回后首领消失

后续已升级为全地图共用的传送规则，移除守望者专用入口硬编码，详见《晶塔条件加载统一修复-2026-10-28》。下文保留最初复现与专项验证记录。

## 原因与修复

原生 `Ruins2_03` 的条件加载器仅在指定进门记录 `top1` 成立、且原生战斗完成状态允许时，载入 `Ruins2_03_boss`。自放晶塔以前选择枚举到的第一个场景入口，并未同步 `TransitionPoint.lastEntered`，因此到其他地图活动再传回时，会留下错误或过期的进门记录：主房间正常载入，首领子场景没有载入。这个过程没有击杀，图鉴保持「发现」符合实际状态。

- 新放的守望者房间晶塔保存正确的原生加载入口。
- 实际传送时也归一化守望者房间入口，兼容旧晶塔已保存的 `bot1` 等入口，不需要修改存档。
- 场景开始加载前同步实际入口记录，原生条件加载器能在正确时机完成首领加载。
- 到达位置仍是晶塔旁。战斗仍由原生控制器触发，使用原来的六名骑士和胜利流程。
- 保留所有原生完成状态与条件检查：不会直接增加图鉴击败次数，也不会让已击败的守望者复活。

更新后完全退出游戏再启动，离开该房间并传送回来即可重新走正确加载流程。无需拆除旧晶塔或重开存档。

## 隔离实机验证

测试通过真实放置路径在电梯与战斗区域之间放置晶塔，将入口保留为旧记录 `bot1`。禁用修复并模拟从其他房间返回时，成功复现房间存在、首领子场景缺失、图鉴未记击败；启用修复后同一晶塔恢复六名首领，原生开场、六名实际死亡、图鉴单次结算与原生胜利记录均正常，胜利后再次传送不重生。
