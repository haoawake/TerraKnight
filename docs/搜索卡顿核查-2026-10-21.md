# 搜索与材料追踪卡顿核查

用户反馈全局掉帧，尤其点击搜索。使用 Test2 独立副本、隔离存档、1280×720 可见窗口复现，正式游戏进程未被中断。

## 已确认原因

- 正式版 `[Debug] FrameProfiler = true`，大量游戏和模组每帧方法被插入计时回调；正式日志可见五秒内数千万次计时回调。配置已单独备份并关闭，需要重启正式游戏卸载当前进程中的计时补丁。
- 第一次掉落查询在单帧内生成各地区的实际掉落表；修复前首次“远古”扫描 583.76 ms，包含实际界面更新的一帧为 686 ms。
- 向导材料来源索引在绘制时同步扫描所有敌人、地区和阶段，首次调用 1234.95 ms。
- 各物品分配来源时反复生成相同阶段和路线的怪物名单；图鉴每个物品的概率也反复遍历完整掉落表。
- 点击已有搜索框会清除结果缓存；IME 启用命令原先在每帧和绘制阶段反复发送。

## 修复

- 查询每帧约 2 ms 预算，未完成时显示“搜索中…”，修改查询会放弃旧任务。IMGUI 同帧多次调用只处理一次预算；只有完整的新结果可点击，避免旧结果与新查询混用。
- 来源索引按单个敌人、地区、阶段分片，每帧约 2 ms，未完成时显示检索状态，暂缓依赖该索引的叶节点操作。
- 缓存相同阶段/路线的来源怪物名单，筛选条件及最终排序与原逻辑一致；保留原先的双来源分配方式。
- 概率显示按组批量计算分母，再合并同物品的独立与互斥抽取；实际战斗掉落逻辑未修改。
- 图鉴缺失贴图排队加载；描边文字复用 GUIContent 并直接绘制，减少持续分配。
- 搜索框获得焦点不重建结果，输入法只在开始输入、换设备及窗口重新获得焦点时启用，候选框位置只在变化时更新。
- 缓存补充难度、领取状态、首次击杀、进度和存档对象等条件，避免状态变化后继续使用过期内容。
